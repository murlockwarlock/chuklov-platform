# Security Architecture

Primary controls: server-derived organization context, explicit membership roles/policies, scoped queries, private storage, secure sessions/CSRF, verified webhooks/Mini App auth, encrypted integration credentials, minimal queue payloads, safe logs, dependency audits, and cross-boundary tests.

M1 adds organization-scoped clients, channel identities, consents, settings, feature controls, credentials, and audit events. M2 adds a server-session client portal context, passwordless email-code authentication, verified Telegram initData signature validation through Nutgram, auth-date freshness/clock-skew checks, one-time replay protection, single-use Telegram connection tokens, session regeneration after Client authentication, and identity resolution only through the current organization. Application actions verify current organization context and feature entitlement; UI visibility is not the authorization boundary. Email codes and Telegram connection tokens are hashed/not persisted in plaintext and never enter logs or audit metadata. Versioned legal documents and consent evidence are organization/document scoped with immutable published content. See REQ-SEC-*, REQ-EMAIL-001, REQ-LEGAL-001, ADR-013, and ADR-015.

Credential values are stored with Laravel encrypted casts, replace operations update rotation metadata, and normal model/API representations are masked. Audit metadata is bounded by an action-specific allowlist before persistence. Audited M1 mutations persist their state change and audit event in one database transaction. Logging taps redact complete sensitive context and message values on every configured emitting channel, including authentication headers and exception context.

M0 repository controls deny the working tree from Docker build context except the reviewed runtime Dockerfiles, scan reachable history and the working tree for secrets, preserve an existing `APP_KEY` during repeated setup, and keep tenant/administrator fields outside ordinary User mass assignment. M2 never logs raw Telegram initData, auth headers, cookies, or identity payloads; audit metadata stores only action-allowlisted source/channel fields.
